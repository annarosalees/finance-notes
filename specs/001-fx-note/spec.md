# Feature Specification: FXノート（`notes/fx.md`）の新規作成

**Feature Branch**: `001-fx-note`

**Created**: 2026-09-16

**Status**: Draft

**Input**: User description: "README で予告されているFX（外国為替証拠金取引）ノート `notes/fx.md` を、`notes/cfd.md` と同じ4部構成（商品概要／価格・損益の仕組み／実務上の扱い／つまずきポイント）で新規作成する。日本語版（`notes/fx.md`）と英語版（`notes/fx.en.md`）を対で作成し、README.md／README.en.md の該当リンクも更新する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - FXの仕組みを基礎から理解する (Priority: P1)

これからFX/CFD実務に関わる読者が、`notes/fx.md` を読んで「FXとは何か」
「なぜ為替差益・スワップという概念で損益が決まるのか」を、専門用語に
頼りすぎない説明で理解できる。

**Why this priority**: README で「収録ノート」として明示的に予告済みの
最初の未着手ノートであり、既存の `notes/cfd.md`（CFDの一種としてFXに
言及済み）と対になる内容のため、優先度が最も高い。

**Independent Test**: `notes/fx.md` 単体を読み、「CFDとの関係」「通貨
ペアの建値・pips」「証拠金・レバレッジ」「スワップポイント」を、他の
ノートを参照せずに説明できるかで検証できる。

**Acceptance Scenarios**:

1. **Given** FX初心者の読者、**When** `notes/fx.md` の「FXとは何か」節
   を読む、**Then** FXがCFDの一種（通貨ペアを対象にした差金決済取引）
   であることと、`notes/cfd.md` との関係を理解できる。
2. **Given** 読者、**When** 「価格・損益の仕組み」節を読む、**Then**
   pips・レバレッジ・証拠金・スワップポイントの4つの用語がそれぞれ何
   を指すか説明できる。

---

### User Story 2 - 実務上の扱い（レート生成・カバー）を理解する (Priority: P2)

証券会社側の実務に関わる読者が、FXレートがどのように生成され、カバー
ディールがどう行われるかを理解できる。

**Why this priority**: README・既存ノートで一貫している「実務者視点」
という差別化ポイントであり、読者が他の入門資料と区別してこのノートを
読む主な理由になるため。

**Independent Test**: 「実務上どのように扱われるか」節だけを読み、レー
ト生成とカバーディールの基本的な流れを自分の言葉で説明できるかで検証
できる。

**Acceptance Scenarios**:

1. **Given** 読者、**When** 「実務上どのように扱われるか」節を読む、
   **Then** インターバンクレートを基にした社内レート生成の考え方と、
   カバーディールの目的（在庫リスクの調整）を説明できる。

---

### User Story 3 - つまずきやすいポイントを事前に把握する (Priority: P3)

読者が、FX特有の誤解しやすいポイント（スワップの正負、レバレッジ規制、
週末のレート変動リスク等）を事前に把握できる。

**Why this priority**: 他ノートと同様の構成要素だが、実務理解の土台
（P1・P2）が先に必要なため優先度は最も低い。

**Independent Test**: 「つまずきやすいポイント」節のみを読み、少なく
とも3つの誤解しやすいポイントを挙げられるかで検証できる。

**Acceptance Scenarios**:

1. **Given** 読者、**When** 「つまずきやすいポイント」節を読む、
   **Then** スワップポイントが正負どちらにもなり得ること、国内FX業者
   のレバレッジ規制（最大25倍等）、週明け窓開けリスクの3点を含む複数
   の注意点を把握できる。

### Edge Cases

- 読者が `notes/cfd.md` を未読の状態で `notes/fx.md` から読み始めた場
  合でも、FXとCFDの関係が分かるよう、該当箇所からリンクを張る。
- 英語版 (`notes/fx.en.md`) の初版が日本語版より内容が少ない場合、どこ
  までが「完了」でどこからが「未翻訳」かをREADME.en.mdの記載方針に沿っ
  て明示する（`notes/cfd.en.md` で既に生じている乖離を繰り返さない）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `notes/fx.md` は `notes/cfd.md` と同じ4部構成（商品概要
  ／価格・損益の仕組み／実務上の扱い／つまずきやすいポイント）に従う
  こと（constitution 原則II）。
- **FR-002**: 「商品概要」節は、FXがCFDの一種（通貨ペアを対象にした差
  金決済取引）であることを明示し、`notes/cfd.md` への相互リンクを含む
  こと。
- **FR-003**: 「価格・損益の仕組み」節は、最低限 pips、レバレッジ、証
  拠金、スワップポイントの4用語を平易な言葉で説明すること。
- **FR-004**: 「実務上どのように扱われるか」節は、レート生成（インタ
  ーバンクレートを基にした社内レート生成）とカバーディールの考え方を
  説明すること。
- **FR-005**: 「つまずきやすいポイント」節は、最低3件の誤解しやすいポ
  イントを挙げること。
- **FR-006**: 特定の企業・システムの内部情報を含まないこと（constitution
  原則III）。
- **FR-007**: 投資助言と解釈されうる断定的な売買推奨表現を含まないこと
  （constitution 原則IV）。
- **FR-008**: 英語版 `notes/fx.en.md` を同時に作成し、日本語版と対応す
  る見出し構成を持つこと（constitution 原則I）。英語版の翻訳が日本語版
  に対して部分的な場合は、未翻訳部分をノート内に明示すること。
- **FR-009**: `README.md`・`README.en.md` の「収録ノート」一覧から
  `notes/fx.md` への記載を「作成予定」から作成済みの状態に更新すること
  （このspecの範囲では、ノート本文自体の執筆と合わせて別タスクとして
  扱う — 本specはfx.mdの仕様定義のみを対象とし、README更新は後続の
  `/speckit-tasks` で扱う）。

### Key Entities

- **FXノート (`notes/fx.md` / `notes/fx.en.md`)**: 既存の `notes/cfd.md`
  と対をなすドキュメント。4部構成、日英ペアという属性を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: FX未経験の読者が `notes/fx.md` を読了後、pips・レバレッ
  ジ・証拠金・スワップポイントの4用語すべてを自分の言葉で説明できる。
- **SC-002**: ノートの4部構成すべてに実質的な内容（プレースホルダでな
  い本文）が存在する。
- **SC-003**: 「つまずきやすいポイント」節に3件以上の具体的な注意点が
  記載されている。
- **SC-004**: 日本語版・英語版の見出し構成（節の数・順序）が一致して
  いる。

## Assumptions

- 対象読者は `notes/cfd.md` と同じく「これから金融実務に関わる人」で
  あり、金融の専門知識は前提としない。
- レバレッジ規制等の数値（例：国内最大25倍）は、特定時点の一般的な制
  度として記載し、法改正等による変更の可能性を断りとして添える。
- 本specの範囲は `notes/fx.md`／`notes/fx.en.md` の仕様定義までとし、
  実際の本文執筆は後続の `/speckit-plan` → `/speckit-tasks` →
  `/speckit-implement` で行う。
- `assets/` 配下への図表追加が必要かどうかは、実装フェーズ（tasks）で
  判断する。
